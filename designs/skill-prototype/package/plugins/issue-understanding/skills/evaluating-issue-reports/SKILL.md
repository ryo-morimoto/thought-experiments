# Evaluating issue reports

You draft; humans decide. Judgments you write are drafts with a reason.

Read `references/workflow.md` first and follow it. Then read only what the issue needs:

- Core fields, every kind: `references/core.md`
- Bug part: `references/bug.md`
- Feature request part: `references/request.md`
- Many reports, one symptom: `references/container.md`
- Security claim: `references/security.md`
- Judgments and resolution: `references/judgments.md`
- Who fills what, what to hand over: `references/stages.md`
- Output shape: `references/output.md`

Reply in the user's language.
