# 課題の記録を下書きするスキルの試作

[課題とバグの理解の記録形式](../課題の理解の記録形式.md)（第 2.1 版）を、エージェントが下書きするための Claude Code のスキル。`drafting-issue-records/` がスキル本体で、[ryo-morimoto/plugins](https://github.com/ryo-morimoto/plugins) の規約（`SKILL.md` は 1000 字以内の案内、参照は 1 主題 2000 字以内、英語の命令形）に合わせて書いた。

- 状態: 試作。プラグインのリポジトリには、まだ移していない（このセッションからはプラグインのリポジトリで git の操作ができなかったため）。
- 移すときは、`plugins/<名前>/skills/drafting-issue-records/` に置き、`check_limits.py` 相当の検査と、`evals/` の評価ケースを足す。

## 試用の結果

経緯を知らない subagent に、スキルのファイルだけを渡して実際の課題に使わせた。最初の保守者の返答の直前（as_of）までの情報だけで記録を作り、その後の経過と比べた。

| 試用 | 課題 | 段階 | 合ったこと | 外したこと |
|---|---|---|---|---|
| バグ | [neovim #32247](https://github.com/neovim/neovim/issues/32247) | 2（実行が権限で拒否され 3 に届かず） | 本当の原因（2 つの組み合わせ）が仮説に入っていた。問うたログが報告者の返答でほぼそのまま出た。部品の語の検索で、2021 年に同じ主張で閉じた課題を見つけた（スレッドでは誰も引いていない） | 報告の多義的な語（「閉じる」）を黙って読み替え、保守者の最初の問いを外した。実際の閉じ方は、別の仕組みを直した PR を根拠にした未検証の推測で、それを書く欄が無かった |
| 要望 | [fd #749](https://github.com/sharkdp/fd/issues/749) | 要望者自身の用途が 0 件で、借りた用途を数えるかで 1 未満か 3 | 最初の問い（何に流すか＋代案で足りないか）が、所有者が 4.5 か月後に出した問いとほぼ同じだった。結論（何もしない）が選択肢に入っていた。同じ要望の過去の課題を見つけた | ツール自身の機能を組み合わせた回避策（`fd -t f -X grep -lI .`）を想定できなかった |

試用の記録は [tests/](tests/) にある。

## 試用から直したこと

- 重複の検索: エラー文が無ければ症状の言い回しで（要望は問題の語と解決の語で）検索する。
- 多義的な語は、黙って読み替えず問いにする。引用した仕様の節は全体を読み、反対に読める文も `counter_basis` に残す。
- 要望では仮説の代わりに選択肢を書き、ツール自身の機能を組み合わせた回避策も入れる。
- 結末（`resolution`）に、閉じた根拠・確かめた者・どの仮説に対応するかを持たせる。別の仕組みを直した修正で閉じない。
- 要望の判断に確信度と根拠を足し、値に「保留（需要待ち）」を足した。段階は累積で、借りた用途は出典と時期を書けば数えてよい。
- セキュリティ: `guards` の理由は、(a) 検査を通りつつ欠陥の条件を満たす具体の値か、(b) 検査の効果が失われる状態の段（位置つき）でだけ受け付ける。偽の報告 2 件は止まり、本物の 2 件は通った（[examples/第2.1版_緩めた規則と偽の報告.md](../examples/第2.1版_緩めた規則と偽の報告.md)）。

## 確かめていないこと

- 直した後のスキルは、まだ試用していない。
- 試用は各 1 件で、自己評価（同じ subagent が後から結末を読んで評価した）。結末を先に見ないという約束は守られたと報告されているが、確かめる手段は無い。
- 時間の計測があてにならなかった（バグで調査 6 分・記録 10 分、要望で体感 10〜15 分）。
