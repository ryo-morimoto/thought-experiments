## 3. 評価

### 効いたはずの欄

- **reproduction.results（環境の表）**: 区切りの時点で表にすると、非再現側の行の「チップ」が空になる。二つの行が両方「Monterey」で、差が見えない。空の欄が目に入れば、最初に聞くべきは「どの機械か」だと分かる（推論）。実際には誰も聞かず、M1 で試した協力者の結果（コメント 5）も、報告者の M1 Max とはコア数が違った。
- **hypothesis の how_to_test**: H2 と H5 の確かめ方（GOMAXPROCS を振る、`wrk -t` と組にする、プロファイルを取る）は、どれも報告者が自分の機械で数分で実行できる。実際に GOMAXPROCS を振ったのは報告者の自発（コメント 16、区切りから 2.5 か月後）、プロファイルを頼んだのは 3 年後（コメント 20）。確かめ方を先に書いて報告者に渡せば、2022 年の前半に H5 の形の説明に届いた可能性がある（推論。ただし元の症状が当時の版で同じ原因だったかは確かめられていない）。
- **missing の state**: 「needs-runtime-check（プロファイル）」が残っていれば、マイルストーンを送るたびに「何が欠けているか」が見え、「調べられなかった」（コメント 17）で終わらずに済んだ（推論）。
- **same_bug_condition**: コメント 5 の「最大 32」を「再現した」とも「再現しない」とも読める。閾値を書いておけば「同じバグではない」と決まる。2025 年に症状が起床回数へ移ったときも、「同じバグか」（コメント 28 で報告者が迷っている）をこの欄で判断できた。
- **expected_basis の「以前の動作」と expected_status**: 最終的にメンテナは「短い処理と弱い負荷では寝起きが増えるのは既知の振る舞い」と説明し、報告者も受け入れた（コメント 28）。期待の根拠が「以前の動作」しかないことを最初に書いておけば、「バグか、仕様どおりの不得手か」という問いを早く立てられた（推論）。

### 合わなかった欄、空だった欄

- **diagnosis**: 区切りの時点では空。再現しない報告では、診断より前に「再現する環境を見つける」段がある。空で正しいが、代わりに何を書くかの指示が無い。
- **judgment.upstream**: 本件がすでに上流なので、ほぼ不要。H1（OS の回帰）が支持された場合だけ、Apple への報告として意味を持つ。
- **judgment.validity の値**: 「妥当 | 無効 | 重複 | 情報不足 | 未判断」に、本件の結末が入らない。元の症状は「原因不明のまま再現しなくなった」で、妥当とも無効とも言えない。GitHub の「completed」はこの区別を失っている。
- **related.relation の値**: #73055（報告者が分けた先）と #54622（既知の設計上の課題）が、「同じ原因 | 同じ症状 | 前提 | 試験の問題 | 実装の経緯」のどれにもきれいに入らない。
- **regression_range**: 「最後に動いた版と最初に壊れた版」が対象のソフトウェア（Go）の版を前提にしている。報告者が言う回帰は OS の版で、ハードウェアの世代でもありうる。

### 置き場の無かった情報

- **非再現側の環境**: 再現しなかった人の環境を、再現した人と同じ細かさで求める欄が無い。results の env は自由記述なので、片方だけ詳しくても気づかない。
- **観測の計器**: 「スレッド数」は Activity Monitor で数えていた。2025 年には `powermetrics` を使い、`top` の IDLEW は別物で 0 のままだったとメンテナが注記している（コメント 23）。何で測ったかが結果の解釈を変える。evidence.source に書けなくはないが、claim.observed に計器と定義が無い。
- **時間とともに変わる再現の状態**: 報告者は 2022-01、2022-12、2025-03 に再試験し、結果が変わった。results の各行に日付と版が無いと、「今も起きるか」が分からない。
- **再現できる環境の手配**: メンテナは同僚の M1 を借り、M1 Max の購入も考えた（コメント 4）。最後は遠隔の試験機で再現した。「誰がその環境を持っているか」を書く場所が無い。
- **放置の記録**: マイルストーンの繰り越し（コメント 15、17）は判断の記録だが、judgment.priority には理由と日時しか書けず、「何が欠けて進まなかったか」とつながらない。
- **報告者の仮説**: 報告者は「効率コアが遅いので runtime がスレッドを足す」と推測した（コメント 16、18）。hypothesis に誰の仮説かの欄が無く、エージェントの下書きと報告者の推測が混ざる。
