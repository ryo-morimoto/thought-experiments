## 評価

### 形式を埋めることで棄却が早まったか

- **早まった（推論）。** 提出時点で形式を埋めると、evidence の観測が 0 件、reproduction.artifact が空、diagnosis.chain の第 1 段が書けない、の 3 つが 1 画面で出る。さらに H1 の確かめ方（`randstr` の出どころを遡る）は、ソースの 571–581 行を読むだけで終わり、E2 で棄却できる。保守者が実際に #2 で尋ねたのは H1・H2 そのもので、形式は保守者の判断を代わりにしたのではなく、保守者がすでにした判断を**最初の 1 回で閉じる理由として書ける形**にした。
- 実際の手間の大半は #3〜#10、つまり「答えになっていない返答」を 4 回読むことに使われた。形式を**報告者に要求**していれば（下の検査規則）、#3・#5・#10 のような一般論の返答は欄を埋めないので、その場で「未回答」と機械的に判定でき、#9 の通告を #3 の時点で出せた（推論）。

### 弱さを最も早く見せた欄

1. `evidence` の種類の数え上げ（観測 0、主張 3）。ただし試案に「主張」の種類が無く、足す必要があった。
2. `reproduction.same_bug_condition`。溢れる条件を具体の値（`randlen >= 40`）で書かせると、579 行の検査と直接ぶつかる。「同じバグの条件」は本来、最小化のための欄だが、偽の報告では**主張を反証できる形に変える**欄として働いた。
3. `hypothesis.how_to_test`。報告者の主張を仮説に直すと、確かめ方が「ソースを遡る」1 手で済み、棄却の根拠が行番号で残る。

### 流暢な LLM が偽れる欄

| 欄 | 偽りやすさ | 本件での証拠 |
|---|---|---|
| claim の文章、impact、修正案 | 容易 | #0 の Impact と `strncpy` の修正案。#5 の一般論 |
| steps | 容易 | #0 と #10 の手順は動作を観測しない手順でも体裁は整う |
| コードの位置（URL） | 容易（実在する位置を指せる） | #0 の位置は正しかった。誤っていたのは因果 |
| コードの引用 | 容易（ただし機械的に検出できる） | #7 は実在しないコードを「問題のコード」として示した |
| artifact | 体裁だけなら容易 | 3392174 の PoC は自分で「TRIGGERED」と表示するだけ |
| evidence の `checked_by` | 容易（「手動で確かめた」と書ける） | 3392174 の自己申告 |

偽りにくいのは、**受け手が機械で再実行・再照合できるもの**だけだった。

### 欄の変更案と検査規則（本件の証拠つき）

1. **`evidence.kind` に「主張（未確認）」を足し、`checked_by` は受け手側で埋める。** 報告者が書いた「確かめた」は `checked_by` にせず、主張として数える。根拠: 3392174 の自己申告、#0 の R2・R3。
2. **欠陥の主張には「受け手が再実行できる観測」を 1 件以上要求する。** 観測は対象のプログラム自身が出したもの（クラッシュ、サニタイザの出力、対象の出力の差）に限り、報告者の道具が出した表示は数えない（判定器が報告者の側にある成果物は観測でない）。根拠: 3392174 の偽サーバの「TRIGGERED」。
3. **コードの位置は「コミット＋パス＋行」で書かせ、引用したコードはその版のソースと機械で照合する。** 一致しなければ evidence から外す。根拠: #7 の実在しないコード（照合すれば即座に検出できた）、3392174 の版とコードの食い違い。
4. **メモリ安全性などの主張には `taint_path`（入力の出どころから問題の行までの段を、各段の行番号つきで）を要求し、最初の段は攻撃者が制御する入力でなければならない。** 根拠: 本件の決め手は E2（`randstr` の出どころが `Curl_rand`）。経路の第 1 段を書かせれば、報告者自身が書けずに止まる。
5. **`same_bug_condition` に、欠陥が起きる具体の値の条件を要求する**（例: `randlen >= 40`）。根拠: 条件を値で書くと、579 行の検査と直接矛盾する。3392174 では本文の計算（25 < 40）が条件を自分で否定していた。値の条件と本文の数値の整合は機械で検査できる。
6. **`related.relation` に「同じ主張（棄却済み）」を足し、同じパス・同じ行への過去の棄却を自動で引く。** 根拠: 3392174 は 2298307 と同じ行への同じ主張。
7. **`question` への返答を、問いが求めた欄が埋まったかで「回答済み／未回答」と判定する。** 一般論の返答は欄を埋めないので未回答になる。根拠: #2 の 2 問に対し、#3・#5・#10 はいずれも行番号つきの経路も値の条件も示さなかった。
8. **報告者の付けた分類・深刻度を `reporter_labels` に分けて残し、指されたコードとの食い違いを evidence にする。** 根拠: 「Heap Overflow」と、関数内の配列 `keyval[40]`（スタック）の食い違い。

これらのうち 2〜6 は、報告を受け付ける時点で機械が判定できる。人の時間は、機械の判定を通った報告にだけ使える（推論）。
