## 問い1: 主要なシステムと結果（古典的なスキルライブラリ ＋ 2025〜2026年の "Agent Skills"（SKILL.md）研究）

### Takeaway
2023〜2025年は「エージェントが自分でスキル（コードまたは手順書）を作って溜める」研究（Voyager、AWM、ASI、SkillWeaver など）が中心だった。2026年は Anthropic 式の SKILL.md を対象にした実証研究が急に増えた。中心となる結果は次の3つ。(1) 人がキュレーションしたスキルは平均で効く。(2) モデルが自分で書いたスキルは平均すると効かない。(3) 関連するスキルでも害になることが少なくない。

### Cited Findings

**2026年の SKILL.md 系実証研究**
- SkillsBench（arXiv 2602.12670、2026-02、NeurIPS 2026 ポスター）: 11 ドメインの 86 タスク（後の版では 84 タスク）。キュレーションしたスキルは平均通過率を +16.2pp 上げた（ドメインによって SE +4.5pp から Healthcare +51.9pp まで幅がある）。自己生成スキルは平均 −1.3pp だった。NeurIPS 版の表記は +16.4pp で、84 タスク中 18 タスクで悪化（v2 抄録では 16/84）。版によって数値が違うので、引用時は版を明記する必要がある。【検索要約】 — [SkillsBench](https://arxiv.org/abs/2602.12670); [NeurIPS poster](https://neurips.cc/virtual/2026/poster/139353)
- Demystifying Agent Skills（arXiv 2608.14036、2026-08-14、Princeton ほか）: Terminal-Bench Pro/2.0 と SkillsBench で、同じ経験を「生の作業記録（workflow memory）」として渡す場合と「SKILL.md に蒸留して」渡す場合を比べた。成功率は Raw 59.1%、Workflow Memory 55.9%、Skill 61.9%。Skill と Workflow Memory の差は +6.06pp（95% CI [+0.76, +11.36]）。スキルが効く仕組みの 65.7% は「手順のアンカー（procedural anchoring）」で、知識の注入は 4.5% にとどまった。【AI要約】 — [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)
- Agent Skills Can Be Harmful（arXiv 2608.11888、2026-08-12、HUST/Microsoft Research/UIUC）: SkillsBench と SWE-Skills-Bench（490 タスク）に、公開スキルサイト（smithery.ai、skillsmp.com）から意味的に近いスキルを足して比べた。OpenCode と Claude Opus 4.6 を使い、スキルが原因と確認できた失敗を 307 件集めた（機能失敗 125 件、効率退行 182 件）。【AI要約】 — [Agent Skills Can Be Harmful](https://arxiv.org/abs/2608.11888)
- SkillBuffBench（arXiv 2611.22017、2026-11-17）: スキルの与え方を3水準（なし／キュレーション済み／インストール済みライブラリから自動起動）に分け、メモリの有無、4 種のハーネス（Codex、Claude Code、OpenCode など）、複数モデルと掛け合わせる要因計画の設計を示した論文。**結果はまだ載っていない**（「評価は進行中」と明記）。タスクも現時点で4件（材料科学2件、生物学2件）だけ。【一部本文】 — [SkillBuffBench](https://arxiv.org/abs/2611.22017)
- Skill Roulette（arXiv 2611.23266、2026-10-11、SMU/Heidelberg）: コーディングエージェントが関連スキルを実際に起動する率を測る事前登録型の研究計画。4 ハーネス × 2 モデル、計 20,400 試行を計画し、H1〜H9 の仮説を立てている。結果は今回読んだ範囲には無い。動機として「起動確率 0.6 の独立した判断が4回続くと、全部が起動する確率は約13%」という試算を示している。【一部本文】 — [Skill Roulette](https://arxiv.org/abs/2611.23266)
- 生態系の規模: あるマーケットプレイスの掲載スキル数は 2026-01-16 の 2,179 件から 2026-02-05 の 40,285 件に増えた（Ling et al. 2026 を孫引き）。40,585 リポジトリを調べた研究では、547 リポジトリで 2,430 個のスキルが見つかった（Galster et al. 2026a を孫引き）。【一部本文・孫引き】 — [Lost in Implicit Routing](https://arxiv.org/abs/2610.18522); [Skill Roulette](https://arxiv.org/abs/2611.23266)

**古典的なスキルライブラリ／ツール生成（2023〜2025）**
- ASI（Inducing Programmatic Skills for Agentic Tasks、arXiv 2504.06821、COLM 2025）: Web エージェントがスキルを実行可能なコードとして誘導し、実行して検証してから採用する。WebArena で静的ベースラインより成功率 +23.5%、テキストでスキルを保存する AWM より +11.3%、ステップ数は 10.7〜15.3% 減った。【検索要約】 — [ASI](https://arxiv.org/abs/2504.06821)
- Voyager（arXiv 2305.16291、2023）: Minecraft で、スキルを JavaScript コードとして保存する。スキルの説明文の埋め込みで検索し、自己検証に通ったものだけをライブラリに追加する。報告値はユニークアイテム 3.3 倍、技術ツリー到達が最大 15.3 倍速。学習したライブラリを新しいワールドに移して使えることも示した。【既知・未再確認】 — [Voyager](https://arxiv.org/abs/2305.16291)
- Agent Workflow Memory（AWM、arXiv 2409.07429、2024）: 軌跡から自然言語の「ワークフロー」を誘導してメモリに入れる。Mind2Web と WebArena で相対 +24.6% と +51.1% と報告。【既知・未再確認】 — [AWM](https://arxiv.org/abs/2409.07429)
- SkillWeaver（arXiv 2504.07079、2025）: Web エージェントがサイトを探索して、スキルを API（Python 関数）として合成し、練習を通して磨く。WebArena で相対 +31.8%、実サイトで +39.8%。強いエージェントが作った API を弱いエージェントに渡すと最大 +54.3%（WebArena）と報告。【既知・未再確認。なお、今回の検索では 31.8% を確認できなかった】 — [SkillWeaver](https://arxiv.org/abs/2504.07079)
- ExpeL（arXiv 2308.10144、2023）: 成功と失敗の軌跡から自然言語の「洞察」を抽出し、成功軌跡と一緒に検索して使う。パラメータは更新しない。【既知・未再確認】 — [ExpeL](https://arxiv.org/abs/2308.10144)
- JARVIS-1（arXiv 2311.05997、2023）: Minecraft でマルチモーダルなメモリ（計画とその実行経験）を検索して計画に使う。【既知・未再確認】 — [JARVIS-1](https://arxiv.org/abs/2311.05997)
- Cradle（arXiv 2403.03186、2024）: 汎用のコンピュータ操作エージェント。スキルをコードで生成して保存する「スキルキュレーション」の部品を持つ。【既知・未再確認】 — [Cradle](https://arxiv.org/abs/2403.03186)
- ツール作成系: CREATOR（arXiv 2305.14318）はツールを作ってから使う工程を分けた。LATM（arXiv 2305.17126）は強いモデルがツールを作り、弱いモデルが使う。CRAFT（arXiv 2309.17428）はタスク別にツールセットを作り、検証と重複除去をしてから検索する。TroVE（arXiv 2401.12869）は検証可能で効率の良い関数ツールボックスを誘導し、使われない関数を定期的に刈り込む。【既知・未再確認】 — [CREATOR](https://arxiv.org/abs/2305.14318); [LATM](https://arxiv.org/abs/2305.17126); [CRAFT](https://arxiv.org/abs/2309.17428); [TroVE](https://arxiv.org/abs/2401.12869)

**2026年のサーベイ**
- Dynamic Agent Skills: A Lifecycle Survey（arXiv 2607.10113、2026-07-11、CMU）: 2023年から2026-05-31 までの 124 本を監査したサーベイ。「スキル」という語の6つの意味（実行可能コード／自然言語ヒューリスティック／SKILL.md パッケージ／パラメトリックアダプタ／記憶・軌跡／能力ラベル）、8段階のライフサイクル、10個の操作（Add, Refine, Merge, Split, Prune, Distill, Abstract, Compose, Rewrite, Rerank）を提案している。【AI要約】 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- 他に関連するサーベイとシステム（今回は読んでいない、タイトルのみ確認）: SoK: Agentic Skills（arXiv 2602.20867）、A Systematic Survey of Agentic Skills（arXiv 2608.29596）、SkillOS（arXiv 2605.06614、スキルのキュレーションを学習する）、SkillX（arXiv 2604.04804、階層的なスキル知識ベース）、WikiSkill（arXiv 2608.27454）、SkillCorpus（arXiv 2607.15557、公開スキル生態系の統合と評価）。 — [alphaXiv 検索結果](https://www.alphaxiv.org/abs/2607.10113)

### Inferences
- 人がキュレーションしたスキルは平均 +16pp 程度効き、自己生成スキルはほぼ効かない（SkillsBench）。人がキュレーションするリポジトリという前提は、現時点の証拠と整合する。
- 「スキルは効くか」という問いは、2026年後半には「いつ、どの仕組みで効き、どこで害になるか」に移っている。SkillBuffBench と Skill Roulette は結果が未公開なので、2026年11月時点では「現実的な配備条件（ライブラリからの自動起動＋メモリあり）でスキルがどれだけ効くか」は未解決と言える。

### Gaps
- Voyager、AWM、SkillWeaver、ExpeL、JARVIS-1、Cradle、CREATOR、LATM、CRAFT、TroVE の数値は今回一次資料で再確認していない。報告に使う前に、各論文の抄録を確認する必要がある。
- SkillsBench 本文は開いていない（数値は検索要約経由）。

## 問い2: どの粒度と表現（コード対自然言語の手順）が効いたか、その根拠

### Takeaway
粒度は「タスク全体」より「サブタスク」の方が転移する。表現については、タスク成功率の面では自然言語（テキスト／SKILL.md）がコードより転移しやすいという対照実験がある。一方で、推論コストと検証可能性の面ではコードが有利という結果がある。生の軌跡をそのまま渡すより、蒸留した手順書の方が良い。

### Cited Findings
- Break It Down, Pass It On（arXiv 2608.20274、2026-08-20、Stony Brook）: AppWorld、OfficeBench、KramaBench の3ベンチマークで 11 モデルを比べた。タスク全体から誘導したスキルは平均成功率を下げた（テキスト −1.2pt、コード −4.1pt）。サブタスクから誘導したスキルは上げた（テキスト +1.9pt、コード +0.5pt）。テキストはコードよりサブタスク型で +2.9pt、タスク型で +1.4pt 高かった。【AI要約】 — [Break It Down, Pass It On](https://arxiv.org/abs/2608.20274)
- 同じ論文は「スキル有用度 ＝ 特異性 × 抽象度」をタスク実行なしで計算できる指標として提案した。有用度が高いほどタスク成功率は単調に上がった。特異性と抽象度はどちらも単独では成功を予測できず、上げすぎると成功率が下がった。【AI要約】 — [Break It Down, Pass It On](https://arxiv.org/abs/2608.20274)
- Demystifying Agent Skills: 同じ軌跡を SKILL.md に蒸留した場合（61.9%）は、生の workflow memory（55.9%）より良かった。workflow memory は無関係な探索や失敗した分岐を残すので、タイムアウトが 10.6% あった（スキルは 4.4%）。スキルは環境・インフラの失敗を 5.3% から 0.2% に、出力フォーマットの不一致を 7.4% から 3.2% に減らした。アルゴリズムの誤り（8.3% → 7.4%）と静的検証だけで済ませる失敗（12.5% → 11.7%）はほとんど減らなかった。【AI要約】 — [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)
- 同じ論文で、スキルを作るときに成否ラベルを見せないと性能が落ちた。例: Gemini、Terminal-Bench-2、成功3・失敗2の混合で、ラベルありは 0.7462、ラベルなしは 0.4000。【AI要約】 — [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)
- SpeedRunner（Better, Faster, Stronger、arXiv 2608.11338、2026-08-11、JHU）: ScienceWorld、BabyAI、Crafter で、コードとして表したスキル（コーディングエージェントが軌跡をプログラムで分析して誘導する）は推論コストを大きく下げた。BabyAI では最終的な使用量が ReAct の約 1/8。ASI のような追記するだけの方式は、ライブラリが増えるにつれてコストも増えた。ただし強いモデル（Gemini-3-Flash、Qwen-3.5-27B）では、圧縮しすぎて自然言語プロンプト最適化（OPO）より性能が低い場合があった。【AI要約】 — [SpeedRunner](https://arxiv.org/abs/2608.11338)
- ASI: スキルをコードにして実行で検証すると、テキストで保存する AWM より WebArena の成功率が +11.3% 高く、ステップ数は 10.7〜15.3% 減った。【検索要約】 — [ASI](https://arxiv.org/abs/2504.06821)
- サーベイの整理: 書き込み時の抽象化（著述時に蒸留すること）は、読み出し時の要約だけより強いことが多い（証拠グレード B/C）。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- 害になる例（粒度と書き方に関わる）: スキルが原因の機能失敗 125 件のうち 68.8% は「関連するスキルが実装の誤りを招いた」もので、無関係なスキルの誤適用は 1.6% だけだった。効率退行 182 件のうち 62.6% は手順の過剰で、最大の内訳は過剰な検証（36.8%）。文脈の肥大化は 25.3% で、そのうち 43/46 件はスキル本文そのものが原因だった（補助資料ではない）。【AI要約】 — [Agent Skills Can Be Harmful](https://arxiv.org/abs/2608.11888)

### Inferences
- 人がキュレーションするリポジトリでは、1スキルを「サブタスク単位の手順」にとどめ、タスク固有の値や経路を本文に書き込まない方がよい、と推論できる。Harmful 論文で目立った「成果物の置き場所の誤り」（19.2%）と「必須要素の抜け」は、スキルがタスク指示より優先されてしまうことで起きている。
- コードとテキストの優劣は目的によって逆になる。転移と成功率ならテキスト、繰り返し実行するコストと決定性ならコード。SKILL.md は本文が自然言語で、必要ならスクリプトを同梱できるので、この両方を取れる形式だと解釈できる（これは推論で、両者を直接比べた実験は見つけていない）。
- 本文は短くし、チェックリストや検証手順は任意扱いで遅延読み込みにする、という設計が Harmful 論文の効率退行の分析から導ける。

### Gaps
- 「SKILL.md 内のスクリプト同梱 対 純粋な自然言語」を直接比べた対照実験は見つからなかった。
- 1スキルの最適な長さや語数を定量的に示した研究は見つからなかった。

## 問い3: ライブラリが大きくなったときの検索と、失敗のしかた

### Takeaway
SKILL.md の progressive disclosure（名前と説明だけを見せ、エージェントが自分で本文を開く「暗黙ルーティング」）は、無関係なスキルが増えると崩れる。関連スキルがあっても読み込まなくなる。原因は文脈の長さではなく、他のスキルの説明文による意味的な干渉。明示的な事前選択（LLM またはハイブリッド検索）で多くを取り戻せる。

### Cited Findings
- Lost in Implicit Routing（arXiv 2610.18522、2026-10-13、HKU/HUST）: SkillsBench のタスクと正解スキルを固定したまま、無関係なスキルを 0 から 1,000 まで増やした。読み込まれたスキルの再現率は 73.6% から 27.4% に落ち、スキルを1つも読み込まない率は 9.3% から 51.6% に上がった。同じライブラリから「選ぶだけ」を明示的に頼むと再現率は 73.9% を保った。Pass@3 は 51.6% から 38.6% と緩やかにしか落ちない（強いエージェントはスキルなしでも解ける）ので、タスク成功率だけを見るとルーティングの失敗を見逃す。【一部本文】 — [Lost in Implicit Routing](https://arxiv.org/abs/2610.18522)
- 同じ論文で、無関係なスキルが 100 個だけでも再現率は GLM-5 で −24.6pt、Kimi K2.5 で −15.6pt、MiniMax M2.5 で −20.7pt 落ちた。Claude Opus 4.6 は 1,000 個で Pass@3 が 64.9% から 62.2% とほぼ保たれたが、再現率は 81.3% から 30.9% に落ちた（37 タスクの部分集合）。Gemini 3.1 Pro は 77.4 → 43.0、GPT-5.4 は 76.2 → 49.3。単一スキルのタスクでも 91.9% から 38.0% に落ちた。正解の代わりに別のスキルを読み込んだ例は評価全体の 2.32% と少なく、崩壊の説明にはならない。【一部本文】 — [Lost in Implicit Routing](https://arxiv.org/abs/2610.18522)
- 原因の切り分け: 無関係なスキルの説明文だけを隠す（長さは保つ）と、再現率は 63.3%（全部隠すと 63.9%、追加スキルなしは 73.5%）まで戻り、読み込みゼロ率は 62.2% から 23.6% に下がった。原因は文脈の長さではなく、説明文による意味的な干渉と、スキル選びがタスク実行と競合することによる指示の干渉だと結論している。【一部本文】 — [Lost in Implicit Routing](https://arxiv.org/abs/2610.18522)
- 対策: 100 個のときは LLM による事前選択で再現率が 53.3% から 73.0%、Pass@3 が 49.4% から 54.9% に上がった。10,000 個のときはハイブリッド事前選択で再現率 55.2%・Pass@3 50.4%（RAG は 48.5%・41.5%）。RAG は常に5件返すので再現率は高く見えるが、精度は 47.6%/43.9%（ハイブリッドは 99.8%/84.5%）と低い。最適な方式は規模で変わる。【一部本文】 — [Lost in Implicit Routing](https://arxiv.org/abs/2610.18522)
- Demystifying Agent Skills（SkillsBench、候補プールは 5〜100）: 実行時に実際に使ったスキルの精度は 29.6% から 3.3% に落ちたが、タスク成功率は 36.4% から 39.3% とほぼ変わらなかった。オフラインの埋め込み検索（Qwen3-Embedding-0.6B）の top-1 精度は k=5 で 88.3%、k=100 で 76.9%。意味的に似た紛らわしいスキルを混ぜると、70.5% から 53.4% に下がった。プールの大きさより紛らわしさの方が大きなストレス要因だった。スキルの誤適用や無視は skill 条件で 10.0%（raw 0.8%）。【AI要約】 — [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)
- サーベイの整理: フラットな検索は 64〜128 スキル程度の中規模で精度が落ちることが多い（グレード B/C。Single-Agent-Skills、Wild-Skills、AgentSkillOS、SkillRouter、SRA を根拠に挙げている）。目的を絞ったライブラリの方が網羅的なライブラリより良いことが多い（B/C。SkillX の階層化、Wild-Skills の有用性フィルタ、SWE-Skills-Bench / SkillFlow-Bench で、公開スキルの多くは効果がゼロか負）。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- Skill++（arXiv 2611.00544）、SkillBrowser（arXiv 2610.23554）、SPEM（arXiv 2610.26995）、Skill Adapter（arXiv 2611.17007）、LIBRA（arXiv 2611.05445）は、ルーティングを考慮した改良、選択的な露出、構造を考慮した手続き記憶などを提案している（タイトルと抄録冒頭のみ確認、本文は未読）。 — [Skill++](https://arxiv.org/abs/2611.00544); [SkillBrowser](https://arxiv.org/abs/2610.23554)

### Inferences
- 人がキュレーションするリポジトリでは、スキルの説明文（description）が最も重い設計対象になる。他のスキルの説明文が干渉源になるので、紛らわしい説明文の重なりを減らすこと、使っていないスキルをインストールしないこと（ライブラリを絞ること）が効くと推論できる。
- 評価の指標は「タスク成功率」だけでは足りない。「関連スキルが実際に読み込まれたか（起動率と再現率）」を別に測る必要がある。
- 数百以上の規模では、エージェント任せの暗黙ルーティングより、事前選択の段（LLM またはハイブリッド検索）を挟む方がよい。

### Gaps
- 名前空間や階層インデックス（スキルのカテゴリツリー）が暗黙ルーティングの崩壊をどれだけ防ぐかを、SKILL.md 形式で直接測った研究は、今回は本文で確認できなかった（SkillX と SPEM は未読）。
- Skill Roulette（説明文の書き方が起動率に与える影響）の結果は未公開。

## 問い4: 剪定・忘却、追加前の検証、モデル間の転移

### Takeaway
採用前に検証する（実行による検証、成否ラベルの利用）と、検証なしで何でも追加するより一貫して良い。ライブラリが中規模を超えると、剪定と統合は性能を保つために欠かせなくなる。蒸留したスキルは、生の軌跡よりハーネス間で移りやすい。強いモデルが作ったスキルは弱いモデルを大きく助ける傾向がある。

### Cited Findings
- サーベイの整理（グレード A/B）: 書き込み時の検証が強いシステムは、提案をすべて採用するシステムより一貫して良い。EvoSkill、CoEvoSkills、SkillWeaver、ASI、WebXSkill、ContractSkill が根拠。CoEvoSkills では代理検証器を外すアブレーションで通過率が 30pt 違った。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- サーベイの整理（グレード B）: AutoRefine では定期的な剪定と統合を止めると、リポジトリが 4.5 倍に膨らみ、スキルの利用率と通過率が下がった。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- サーベイが挙げる静的ライブラリの問題: ツールやベースモデルが変わると、構文は正しいままでもスキルが動作上は誤りになる（腐敗、stale）。再実行できる検証が必要になる。通常のバージョン管理には「どの軌跡や検証がスキルの採用を正当化したか」という出自の記録が無いので、ロールバックや再採用が難しい。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)
- SpeedRunner: ライブラリの肥大化を、public/private の公開範囲で抑えた（補助関数はエージェントに見せない）。誘導器がスキルの追加・編集・削除を行う。タスク分布が変わっても元のタスクの性能低下は −3.3pt で、推論コストは 27.1% 減った。追記するだけの ASI はライブラリが増えるにつれてコストが増えた。【AI要約】 — [SpeedRunner](https://arxiv.org/abs/2608.11338)
- Break It Down: スキルメモリには、失敗したコードスキルを剪定し、説明文がほぼ重複するものを統合・削除する仕組みを入れた。前述の有用度スコアは、実行前にスキルを剪定する診断に使えると主張している。【AI要約】 — [Break It Down, Pass It On](https://arxiv.org/abs/2608.20274)
- ハーネス間の転移: Codex の軌跡から作ったスキルは Gemini CLI でも、workflow memory や Gemini CLI の素のベースラインより高い成功率を保った。【AI要約】 — [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)
- モデル間の転移: 弱いバックボーンほど相対的な利得が大きいという報告が複数ある（グレード C。SkillWeaver、MetaClaw、EvoSkill、Agentic-Proposing）。 — [Dynamic Agent Skills](https://arxiv.org/abs/2607.10113)。SkillWeaver では強いエージェントが作った API で弱いエージェントが最大 +54.3%（WebArena）【既知・未再確認】 — [SkillWeaver](https://arxiv.org/abs/2504.07079)
- SpeedRunner の傾向は GPT-5.4-mini、Gemini-3-Flash、Qwen-3.5-27B でおおむね保たれた。ただし強いモデルでは圧縮しすぎて性能が下がる例があった。【AI要約】 — [SpeedRunner](https://arxiv.org/abs/2608.11338)
- 自動での原因帰属: SKILLTRIAGE（GPT-5.5、3回の多数決）は、スキルが原因の機能失敗の上位カテゴリを 93.6%、サブカテゴリを 88.8% の精度で当てた。効率退行では上位 79.7%、サブ 72.5%。スキルのマーケットプレイスでの継続的なスクリーニング用途を想定している。【AI要約】 — [Agent Skills Can Be Harmful](https://arxiv.org/abs/2608.11888)
- SkillsBench: 自己生成スキルは平均 −1.3pp（検証なしで自己生成しても効かない傍証）。【検索要約】 — [SkillsBench](https://arxiv.org/abs/2602.12670)

### Inferences
- 人がキュレーションするリポジトリでも、スキルを追加する前に「スキルあり／なし」の対照実行（同じタスク・同じモデルで、成否とコストを比べる）を採用条件にすべきと推論できる。Harmful 論文の差分テストの設計はそのまま採用ゲートに使える。
- 廃棄の基準の候補: (a) 対照実行で成績が負、(b) 起動されない、(c) 他のスキルと説明文が紛らわしい、(d) 依存するツールやモデルが変わった。(c) は暗黙ルーティング崩壊の研究から、(d) はサーベイの stale 問題からの推論。
- 出自の記録（どの検証で採用したか）を SKILL.md のメタデータや変更履歴に残すと、ロールバックと再検証が楽になる（サーベイの主張からの推論）。

### Gaps
- SKILL.md 形式で人がキュレーションしたスキルの「モデル世代をまたいだ寿命（いつ腐るか）」を測った研究は見つからなかった。
- 剪定のスケジュール（いつ、何を基準に消すか）を原理立てて示した研究は、サーベイでも未解決問題として挙げられている。
- AutoRefine、CoEvoSkills、EvoSkill の一次資料は読んでいない（数値はサーベイ経由）。
