2026-11-24 時点。ユーザーの指摘（何をしなければならないかの見通しが無く、その場の判断だけで進めていた）を受けて書いた。新しい作業は、この木のどの節を進めるかを決めてから始める。節を閉じたら、状態と根拠の記録を書き換える。

状態の印: [済] 結論が出た、[一部] 進めたが完了の条件を満たしていない、[未] 手を付けていない、[外] 範囲の外と決めた。

## 根: 健全性の根拠

モデルで性質 P を示したとき、対象でも P が成り立つ（モデル ⊨ P ⇒ 対象 ⊨ P）と言える根拠を与えられるか。対象は 2 つ: (a) 仕様（WHATWG の HTML・Fetch の、固定したコミット）、(b) 出荷中のブラウザ。

これまでの答え: (a) 厳密な健全性は無い（正文が形式的でないため）。(b) 健全性は無く、試験による段階的な確信にとどまる（[2026-11-20-browser-semantics-soundness.md](../experiments/2026-11-20-browser-semantics-soundness.md)、[2026-11-21-formal-source-soundness.md](../experiments/2026-11-21-formal-source-soundness.md)）。残る仕事は、厳密でない根拠を、どの条件のもとでどこまで強くできるかを示すこと。根拠は次の 3 つの包含が揃って初めて立つ。A はモデルの中、B は仕様 ⊆ モデル、C はブラウザ ⊆ モデル。

## A. モデルの中で P が正しく示されている

- A1 [一部] 性質の書き方が正しい（前提を正しい概念で書く）。完了の条件: 各性質の前提の概念が仕様の定義に対応づいている。
  - 済: 前提を「https のオリジン」から「安全な文脈」に直した、方策の容れ物の COEP で書いた（[fixes/](../experiments/models/site-isolation/fixes/FIXES.md)）。理由の形で書いた性質は拡張に耐えた（[informal-extension](../experiments/2026-11-21-informal-extension.md)）。
  - 未: 残りの性質（NoUndeclaredLeak など）の前提の点検。
- A2 [未] 検査が健全である。TLC の有限の領域（オリジン 4〜7、値の種類）で示したことが、無限の領域で成り立つ理由（小さなモデルの定理、対称性）。完了の条件: 領域の大きさを増やしても結果が変わらないことの確かめか、議論。
- A3 [一部] 性質が空でない。完了の条件: 各性質に、前提を満たす証人がある。済: OptInWitness など一部。

## B. 仕様のすべての振る舞いがモデルの振る舞いである（対象 (a)）

- B1 [済] 「仕様」の範囲を決める。取り込まれた本文の固定したコミット。取り込まれていない書き換えは配備の仮定（[informal-extension](../experiments/2026-11-21-informal-extension.md)）。
- B2 段の網羅: P に効く段が、写されているか過近似されている。
  - B2a [一部] 閉包の境界: 取り出しで 415 算法を決めた。境界は手で選んだ（他の仕様からの差し込みは原稿に現れない）。
  - B2b [一部] 落とした段の発見: 落とした段を足して性質が変わるかで確かめる方法（[fsp-correspondence](../experiments/2026-11-21-fsp-correspondence.md)）。型の全体での置き換えは空、契約で範囲を限ると前提の見直しにはなる（[havoc](../experiments/2026-11-23-havoc-unmodeled-steps.md)）。完了の条件: 写していない段のうち、性質に効くものの一覧が閉じている。
  - B2c [未] 書き先の決定: 書き先の 57% が規則で決まらない。段の中の条件の文の意味を決める必要があるか。
  - B2d [一部] 中身が文書に入る経路の一覧: 取得の呼び出しは機械的に拾え、再利用は一部手で（[sink-path-inventory](../experiments/2026-11-22-sink-path-inventory.md)、段階C が未）。
- B3 [済] 実装の選択（実装定義、列挙、任意の段）を過近似として扱う: 依存する入力を明示した関数、仕様の水準では非決定の包み（[opt-enum](../experiments/2026-11-21-informal-enumerated-choice.md) ほか）。
- B4 [一部] 拡張点と支配の条件: 止めるだけの差し込みはアクセス制御を保つ。支配の条件は経路ごとに確かめるしかなく、2 つの経路は本文が保証しない（詳細は伏せた）（[dominance-declassification](../experiments/2026-11-21-dominance-declassification.md)）。
- B5 [未] 情報流（hyperproperty）: 詳細化は保たない。漏らすものの一覧と、攻撃者が入力を選び問い合わせを繰り返す形の検査（自己合成）が要る。ORB の漏れの量は議論で受け入れただけで、動かしていない。
- B6 [済] 厳密な健全性への道: 正文が形式的か、証明の成果物から生成されるか、検証つきの変換があるとき。HTML には無い（[formal-source-soundness](../experiments/2026-11-21-formal-source-soundness.md)）。

## C. ブラウザのすべての振る舞いがモデルの振る舞いである（対象 (b)）

- C1 [済] 値を記録する観測の仕組み: 合否ではなく値を出す試験（[observe/](../experiments/models/site-isolation/observe/RESULTS.md)）。
- C2 [一部] 入力の空間の網羅: 軸に沿って筋書きを機械的に作る（[axis-generated](../experiments/2026-11-24-axis-generated-scenarios.md)）。入れ子とスキームと COEP の軸は済。完了の条件: 性質が量化する入力の構造（リダイレクト、popup の系譜、sandbox、about:blank、履歴）を軸として覆い、等価のまま残る変異体が軸の外だけになる。
- C3 [済] 判別の力の測り方: 変異体を観測で殺した数。モデルの上で全体を先に調べ、ブラウザで動かす筋書きを選ぶ。
- C4 [一部] 仕様の時点とブラウザの食い違いの扱い: Chrome の Origin-Agent-Cluster は未統合の #7617。完了の条件: 食い違いごとに、モデルのパラメータ（配備の仮定）にするか、ブラウザの欠陥とするかを決める。
- C5 [外] API より下の層（プロセスへの配置、Spectre）: 観測できる値はプロセスの隔離を映さない。範囲の外と明記する。
- C6 [一部] 観測の仕組みの妥当性: 手元のコンテナと wpt.fyi の条件の違い、試験の作りの影響（w014 のポート）。
- C7 [未] 版と構成: 版や端末で変わる選択（cross-origin isolation mode が platform で変わる可能性）。

## D. 列と合成の性質

- D1 [一部] 列の性質（ナビゲーションの列、リダイレクト、bfcache、履歴の移動）: モデルの多くは 1 回きりの関数で、1 回きりの筋書きの包含は列の性質を支えない（反例: リダイレクトの途中の COOP を無視するモデルでも 109 件はすべて内側）。NestedHistory.tla は一部。完了の条件: 列を状態の遷移として写したモデルと、列の筋書きでの包含。
- D2 [一部] 断片をまたぐ合成（assume-guarantee）: 仮定の循環の問題が指摘された。

## 根への効き方（優先の考え方）

根の答えを強くするのは、B と C の「完了の条件」を満たすこと。A2 は B・C のどちらにも効く前提。D1 は、性質を列で書く限り B と C の両方を条件つきにしている。いちばん大きく効く未完了の節は、C2 と D1（ブラウザについて、1 回きりの点を超えて列の性質へ届くか）、B2b と B2c（仕様について、写していない段の一覧を閉じられるか）、A2（有限の領域での検査が何を言うか）。F は根に効かない。
