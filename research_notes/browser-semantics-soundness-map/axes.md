# 地図「ブラウザの意味論から検証モデルへの変換の根拠」の軸

地図: [maps/browser-semantics-soundness/map.toml](../../maps/browser-semantics-soundness/map.toml)。元の思考実験: [experiments/2026-11-20-browser-semantics-soundness.md](../../experiments/2026-11-20-browser-semantics-soundness.md)。

## 決めた軸（ユーザーの判断、2026-11-21）

- 行: 攻撃者の模型。Akhawe ら（CSF 2010）の Web の攻撃者・能動的なネットワークの攻撃者・ガジェットの攻撃者と、Reis ら（USENIX Security 2019）のレンダラーを乗っ取る攻撃者・メモリを読み出す攻撃者。
- 列: 性質の種類。Clarkson と Schneider（JCS 2010）の安全性・活性・ハイパー安全性・ハイパー活性。

選んだ理由: 元の思考実験の答えは、攻撃者（仕様どおりのスクリプトか、レンダラーの乗っ取りか、サイドチャネルか）と、性質の種類（アクセス制御か、情報流か）で分かれた。この 2 軸なら、その結果をそのままセルに置ける。2 軸は独立で、どの攻撃者にもどの性質の種類も考えられる。

3 つの出典は、どれも本文で値の定義を確かめた（論文の PDF を取得して該当箇所を読んだ）。

## 捨てた候補

| 候補 | 捨てた理由 |
| --- | --- |
| 攻撃者 × 根拠の種類（SWEBOK v4 や IEEE 1012 の検査・試験・モデル検査・証明・実行時の監視） | 根拠の種類は、この地図の問いの答えそのもの（どんな根拠を与えられるか）にあたり、軸にすると答えを先に区切ってしまう |
| 仕様の可変性（W3C QA Framework: Specification Guidelines の discretionary items など） × 性質の種類 | 取り出しの実測で残りが集まった「実装の選択」を軸にできるが、攻撃者による答えの分かれ方が見えなくなる。出典の本文も確かめていない |

## 行に無いもの

攻撃者のいない場合（イベントループのタスクの順序など、機能の正しさ）は、どの出典の攻撃者の値にも当たらないので行に入れていない。元の思考実験の①（攻撃者のいない安全性性質）は、この地図の外にある。
