# 思考実験の記録

思考実験は、会話の中だけに置くと、要約やセッションの終わりで途中経過が失われます。ここに、段階ごとに書き残します。

## いつ書くか

| 契機 | 何をするか |
| --- | --- |
| **段階A が終わったとき** | 記録を作る（`状態: 設定中`）。問い・用語・モード・対立仮説・設定の欠陥・試し打ちを書く |
| **段階B の操作を終えるたび** | 「経過」に追記する（`状態: 検討中`）。何を動かし、どの仮説が脱落したか |
| **段階C で結論を出したとき** | 結論を書く（`状態: 結論済み`）。前提ごとの種類（定義上・論証・経験的/未検証）と、生き残った選択肢・脱落した選択肢 |
| **問いを変えたとき・中断したとき** | 今の記録を `状態: 分岐` か `状態: 中断` で閉じ、理由と分岐先の記録へのリンクを書く |
| **方針やツールを変えるとき** | 根拠になった記録のパス（`experiments/….md`）を、変更箇所のコメントやコミットメッセージに書く。記録は同じコミットか、それより前に存在すること |

1 ターンごとには書きません。書くたびに、その段階の内容をコミットします。

最後の契機だけは機械で検査します。`data-policy.toml`・`DATA_POLICY.md`・`README.md` で「思考実験」に触れた箇所には、近く（前後2行以内）に `experiments/….md` へのパスが必要で、そのファイルは実在しなければなりません（`tools/check_data_policy.py`）。

## 書き方

ファイル名は `experiments/YYYY-MM-DD-<slug>.md`（日付は開始日）。先頭に次の項目を書きます。

```markdown
# <問い>

- 状態: 設定中 | 検討中 | 結論済み | 分岐 | 中断
- 開始: YYYY-MM-DD
- 更新: YYYY-MM-DD
- 関連: <ほかの記録・報告書・調査メモ・地図へのパス>
- 木の節: <木>/<id>（plan/<木>/tree.toml の節。複数は「、」で区切る。どの木にも属さないなら「なし」）
```

本文は「問い」「前提」「条件を変える」「結果を攻撃する」「結論」「次の問い」の順に書き、段階ごとの記録を「経過」に日付つきで足していきます。脱落した仮説は消さず、理由と一緒に残します。

事実は出典つきで、推論は推論と書きます。確かめていないことは「未検証」に並べます。

## 具体を残す

結論や論証（抽象）だけでなく、それを支えた具体も「具体」の節に残します。後から同じ判断を再現・検証できるようにするためです。[DATA_POLICY.md](../DATA_POLICY.md) に準拠するものはそのまま、準拠しないものは参照で残します。

| 具体 | 残し方 |
| --- | --- |
| 規約・論文などの文章 | 必要な部分だけを引用し、出典 URL と、あれば Internet Archive の保存先・sha256 を書く（DATA_POLICY.md 1.3） |
| 法令・判決 | 条文をそのまま載せ、出典を書く（著作権法13条、DATA_POLICY.md 1.2） |
| 使ったデータ | リポジトリにあればパス。抜粋は DATA_POLICY.md 1.4 に従う。使わないと決めたデータは取得元 URL・保存先・sha256・過去のコミットだけ |
| 検査や試験の結果 | 実行したコマンドと出力（自作物） |
| 外部の記録 | CI の実行、attestation、Internet Archive の保存先などの URL |
