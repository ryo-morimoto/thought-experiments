# Implementation ⊆ model: observed values vs. the values SpecIsolation allows

This is a herd/litmus-style check. For each of the 109 WPT rows in `../wpt-cases.tsv` we recorded
the value Chrome and Firefox actually produce. We then checked that each value is in the set of
outputs `../SpecIsolation.tla` allows for that row. A subagent ran this on 2026-11-23.

## Setup

- podman (`docker.io/library/python:3.12-bookworm`), WPT clone 31362d122, `./wpt run --headless
  --timeout-multiplier=4`; Chrome 158.0.8127.36 and Firefox 160.0.1 (raw logs' `run_info`).
- Each observation file ran twice per browser (own `wpt run` each); the original WPT files
  (`driver/originals.txt`) ran once per browser for local PASS/FAIL. Tests do not assert: each
  observation is a passing subtest `OBS <row> :: <value>`.
- Value mapping: `fetch()` gives `response.type`, or `error` on a TypeError; `<img>`/`<script>`
  give `load` or `error`; `crossOriginIsolated` and `originAgentCluster` give the getter's value.
  PopupSevered is `TRUE` when `popup.closed` and the popup's `opener` is null, `FALSE` when open
  with a non-null opener (other pairs kept raw; none occurred). DocumentDomainNoOp is `TRUE` when,
  after setting `document.domain`, sync access is still refused or the child's value is unchanged.
- Inputs are those of the original tests: same URLs, host tokens, header values (via `.headers`
  or wptserve `pipe=header(...)`), modes and order. WPT helpers (`popup-test.js`, `helpers.mjs`,
  dispatcher, `credentialless/resources/common.js`) are loaded at run time and not copied here.

## Allowed sets (AllowedSets.tla)

- `driver/mkallowed.py` generates `AllowedRows.tla`: `Allowed(m, r)` is the set of outputs of
  `S(m) == INSTANCE SpecIsolation WITH Mutant <- m` on row r, over COIChoice ∈ `COIChoices`
  (CrossOriginIsolated rows: union with the `param:coi-logical` run; OAC rows with a concrete
  mode: both `concrete` and `logical`).
- HTML's agent-cluster steps (`obtain a similar-origin window agent`) and its popup COOP steps
  contain no "optionally" or "implementation-defined" choice (checked in the HTML text snapshot),
  so the model has no other parameter.
- Element rows (w014–w022) are projected: basic/opaque → `load`.
- Under {concrete, logical}, the allowed set has two values for w063 and w067–w071
  ({FALSE, TRUE}) and one value for every other row.

Cfgs (rerun all with `bash driver/check.sh <out dir>`):
- `AllowedSets.cfg`: observations, COIChoice ∈ {concrete, logical}.
- `AllowedSets-concrete.cfg` / `AllowedSets-logical.cfg`: observations, one COIChoice only.
- `AllowedSets-expected.cfg`: the TSV `expected` column fed in as pseudo-observations, to check
  the pipeline. All 109 rows fall inside, and `popup-no-sap-exception` is killed on exactly
  w027/w030/w033, as before.

Chrome reports every secure-context window as origin-keyed, even with no header or a `site`
historical key (w077, w086, w093); over http it reports false (w102, w103 inside). The HTML text
says "without web developer action" the key is a site, so this is outside that text, stricter
rather than weaker, and already public as failing tests on wpt.fyi.

None of the out-of-model values weakens a check (no extra `opaque`, no unsevered popup, no
unexpected cross-origin isolation), so nothing was held back under `held/`.

## Discrimination control (mutants)

The mutants are the 27 `neg:` MechMutants plus the 16 named Mutants, 43 in all. A mutant m counts
as **killed** by browser b when some row's observation is inside `Allowed(none, r)` but outside
`Allowed(m, r)`. Observations that fall outside the unmutated model cannot kill anything. Without
this rule, Chrome's 17 out-of-model rows would "kill" every mutant that leaves them alone.

| COIChoices | browser | killed | equivalent on the 109 rows | differ but survive |
| --- | --- | --- | --- | --- |
| {concrete, logical} | Chrome | 38 | 3 | 2 |
| {concrete, logical} | Firefox | 38 | 3 | 2 |
| {concrete} | Chrome | 40 | 3 | 0 |
| {concrete} | Firefox | 40 | 3 | 0 |
| {logical} | both | 33 (and w063, w067–w071 out of model) | 10 | 0 |
| {concrete, logical} | TSV expected | 38 | 3 | 2 |

- Both browsers kill the same set of mutants, though sometimes on different rows. Chrome has
  fewer OAC kill rows.
- Equivalent on these rows: `cl-ignore-creds`, `crossorigin-as-site`, `neg:coep-cl-strips`.
- The survivors under {concrete, logical} are `coi-ignore-secure` and `coi-coop-only`. Both only
  add `TRUE` where the base model says `FALSE`. The logical branch already allows `FALSE`, so an
  observed `FALSE` (w064, w066) cannot reject them. Fixing COIChoice to concrete kills them on
  w064 and w066. The union lets a browser pick concrete on one row and logical on another; a
  browser fixes it once. Both report TRUE on w063/w067–w071, which is outside the logical-only
  sets, so the observations identify COIChoice = concrete for both, and 40/43 is the consistent
  figure (38/43 is the conservative bound).
- Observations outside the model that a mutant would let in: `neg:oac-coi` lets in all 12 of
    Chrome's out-of-model getter rows, but Chrome still kills it on w098/w099 and w102/w103: Chrome
    acts as "origin-keyed unless non-secure", which none of the 43 mutants expresses (the 4
    document.domain rows take the key kind as input, so no mutant can let them in). w014 is allowed by `samesite-as-origin`, `neg:corp-ss-site`, `neg:corp-ss-scheme`,
    `neg:corp-first-pass` and `neg:fetch-blocked`. That only says that "error" is reachable from
    a misread CORP check; the actual cause is outside CORP.

Inclusion is not vacuous: 38–40 of 43 mutants are rejected. However, the observations kill
exactly the mutants the TSV expectations already kill. On these 109 scenarios, browser values
add no discrimination beyond the WPT expectations the model was fitted to.

## What this shows

- **Firefox 160:** 108/109 values are allowed; w014 is a cause the model omits (Mixed Content).
  On the four modelled operators Firefox stays inside the model at every tested point. This is
  support for the model's proofs on 109 points, not a refinement proof.
- **Chrome 158:** FetchResult, PopupSevered and CrossOriginIsolated have the same support as in
  Firefox. Statements about OriginAgentCluster/document.domain do not transfer: Chrome is
  origin-keyed where the model says site-keyed (16 rows). Checking Chrome would need a model
  parameter "key is always origin on secure contexts"; the deviation is towards more isolation.

## Limits

- DocumentDomainNoOp rows take the key kind as an argument, so no mutant can change them; they do
  not discriminate. Element rows only show load/error. No row is cross-origin `cors`.
- Fetch rows observe `response.type`, not bodies, timing or other side channels.
- One host configuration (wptserve's hosts), 2 repeats, no Safari. The parameter set is the one the
  model exposes; optional browsing context group swaps (`../bcg-observe`) are outside these operators.
