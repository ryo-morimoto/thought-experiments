# 写していない段を任意の値に置き換えても性質が残るかで、手書きのモデルの健全性を閉包に対して確かめられるか

- 状態: 結論済み
- 開始: 2026-11-23
- 更新: 2026-11-23
- 関連: [experiments/2026-11-20-browser-semantics-soundness.md](2026-11-20-browser-semantics-soundness.md)（元の問いと結論 (a)）、[experiments/2026-11-21-fsp-correspondence.md](2026-11-21-fsp-correspondence.md)（落とした段を足して性質が変わるかで確かめる）、[experiments/2026-11-21-informal-extension.md](2026-11-21-informal-extension.md)（契約つきの差し込み）、[SpecIsolation.tla](models/site-isolation/SpecIsolation.tla)、[extract/README.md](models/site-isolation/extract/README.md)

## 問い

これまでの結論は、どれも「写した分については成り立つ」で終わっていた。モデルが段を落とすと、WPT はそれを捕まえにくい（109 件が「安全でない文脈の COEP」の欠落を捕まえなかった）。

そこで、取り出した閉包（415 算法、3445 段）のうち、モデルが写していない段で、モデルが読む値（COEP の値、COOP の値、CORP、要求の資格情報、エージェントクラスタの鍵、グループの cross-origin isolation mode など）を書くものを、すべて「その型の任意の値」に置き換える。それでも性質が成り立てば、その性質は、写していない段の中身によらず閉包に対して成り立つ。この方法で、元の問いの結論 (a)「取り出しで得られるのは追跡可能性だけ」を、検査できる主張に変えられるか。

問いの出し方（ユーザーの判断）: ブラウザの意味論から検証モデルへの変換の健全性を評価するうえで価値があるものから進める。不確実性が高いもの、一度やり方を見つければ他にも流用できるものを優先する。Claude はこの方法を 1 位に挙げた。理由は、どの結論にも共通する「写した分だけ」という限界を検査の対象にすること、既存の誤読の包み C(id, e) と拡張点の差し込みの一般化で、他の断片にも流用できること。

## 前提

- 置き換え（havoc）は、誤読の包み `C(id, e)` に、型の全体を動く `havoc:<id>` を足す形で入れる。拡張点の差し込み（ExtensionHooks.tla）で、契約が許すすべての値を量化したのと同じ考え方。
- 安全性の性質（OptInOnlySecure、理由の形の COIOnlyWithOptIn）に限る。情報流の性質（NoUndeclaredLeak）では、比べる 2 つの実行で置き換えが違う値を選ぶと、それだけで性質が崩れる（詳細化の逆説）。情報流は、両方の実行で同じ値を選ぶ置き換えで別に扱う（次の思考実験）。
- 「モデルが読む値を書く段」を、取り出した段の表（closure_steps.tsv、代入の形の段 1356）から、書き先で選ぶ。書き先を決められない段（「追加する」「タスクを積む」「段を走らせる」など）は、穴として数える。
- 対照を 3 つ置く（前に、判別の力の無い尺度で一度誤った。無作為な根の閉包の基準）。
  1. 陽性: 既知の 2 つの欠落（`false:coep-insecure`、`false:coep-cl-strips`）を再現した段を置き換えると、置き換えはそれを捕まえなければならない。
  2. 陰性: どの性質も読まない値を書く段は、置き換えても性質が変わらないはず。
  3. 基準: 同じ数の無作為な段の集合。置き換えがほとんど何でも捕まえるなら、方法は空で、それ自体を結果として書く。
- モード: 構成的（方法を作り、対照で確かめる）。採らなかった候補は、破壊的（方法が空であることを示す）。

対立仮説:

- R1 働く。モデルが読む値を書く段は少数で、置き換えても安全性の性質の多くは残り、残らないものはモデルの本当の欠落を指す。結論 (a) は「性質ごとに、閉包に対して健全か検査できる」に変わる。
- R2 空になる。置き換えはほとんどすべての性質を崩す（モデルが読む値は、閉包のどこかで必ず任意に書かれる）。方法は判別の力を持たない。
- R3 書き先を決められない。段の多くは書き先が自然言語で、型と結びつけられず、置き換える段の集合そのものが手で選ぶものになる（取り出しの 91.3% は形の話で、書き先の話ではない）。
- R4 境界が効く。置き換えで性質が残っても、閉包の境界の外（拡張、他の仕様、再利用の経路）からの書き込みは測れないので、主張は「閉包に対して」に限られる。

設定の欠陥: 置き換える値の型は、モデルの型（COEPs、COOPs、CORPs など）を使うので、モデルが型を狭く取っていれば（値の種類を落としていれば）、置き換えもそれを見落とす。陽性の対照は既知の 2 つの欠落だけで、未知の欠落の再現率は測れない。

## 条件を変える

固定: SpecIsolation.tla（2 段を足した版）、取り出した段の表。変える: 置き換える段の集合と、置き換える値の範囲（ユーザーの判断: 先行研究のあと、1 位と並行で進める）。

**対照**

- 陽性（安全でない文脈の COEP）: 通った。段を落とすと OptInOnly が成り立って見え、その段の置き換えで崩れる。ただし、置き換えの点は手で入れたもの。段を落とした版では、安全な文脈の点が見えなくなった（モデルが読まない値への書き込みは、置き換えでは見えない）。
- 陽性（credentialless の資格情報を落とす段）: どちらの安全性の性質もこの段に依らないので、性質の水準では確かめられない。振る舞いの水準では通った。
- 陰性: どれも崩れなかったが、どれも構造上崩れようがなかった（値を読まない、守りが働かない、結果が不透明でない）。陰性の対照としての力は無い。
- 基準: 上の無作為な集合。

読み取れること:

- R2（空になる）が、集合の水準で当たった。型の全体で置き換えると、無作為な集合でもほぼ必ず崩れる。
- R1（働く）は、点ごとに範囲を限ったときだけ一部当たった。モデルの本当の欠落を 1 つ、モデルに無い検査への依存を 1 つ、性質の書き方の食い違いを 1 つ見つけた。範囲を限ることは、拡張点の差し込みの契約（ExtensionHooks.tla）と同じ形で、契約は手で書いた。
- R3（書き先を決められない）が当たった。書き先の 57% を規則で決められず、選び方には後から足した規則と手の種が要った。
- R4（境界が効く）が当たった。service worker と cross-origin isolated の能力は手で足すしかなかった。

## 結論

写していない段を任意の値に置き換える方法は、型の全体では空で（無作為な集合でもほぼ必ず崩れる）、閉包に対する健全性の検査にはならない。書く段が作れる値へ範囲を限る契約を手で書くと、モデルと性質の前提の欠落が見つかったが、見つけたのは契約を書く読みで、置き換えそのものではなかった（置き換えは、直す前と後の安全な文脈を区別できなかった）。この方法は、構造化した前提の見直しとして使える。結論 (a)「取り出しで得られるのは追跡可能性だけ」は、この方法では検査できる主張に変わらなかった。

前提:

1. 経験的（TLC）: 型の全体の置き換えは、15 点から 8 点の無作為な集合でも確率 0.9986 と 1.0 で性質を崩す。
2. 経験的（書き先の分類、1 人の判定）: 書き先の 57% は規則で決まらない。
3. 経験的（直したモデル）: 安全な文脈の修正を、置き換えは区別できない。入れ子の枠の検査の修正は、新しく書いた入れ子の性質で見えた。
4. 未検証: 契約が過近似であること、置き換え無しで読む対照。

生き残った選択肢: 「範囲を限った置き換えは、構造化した前提の見直し」。脱落: R1（閉包の水準で働く）。R2〜R4 は当たった。

- 書き先を決めるには、取り出しの段の中の条件の文の意味（半形式の行の残り）を決める必要があるか。

- 2026-11-23 段階A。問いと対立仮説 R1〜R4、3 つの対照を置いた。
- 2026-11-23 段階B。型の全体での置き換えは無作為な集合でもほぼ必ず性質を崩し、閉包の水準では判別の力が無かった（R2）。点ごとに書く段が作れる値へ範囲を限ると、モデルの本当の欠落（安全な文脈）を 1 つ見つけた。書き先の 57% は規則で決められなかった（R3）。
