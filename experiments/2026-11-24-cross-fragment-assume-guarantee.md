# 断片をまたぐ仮定と保証を書き、循環を扱えるか

- 状態: 結論済み
- 開始: 2026-11-24
- 更新: 2026-11-24
- 関連: [plan/browser-semantics-soundness/TREE.md](../plan/browser-semantics-soundness/TREE.md)、[experiments/2026-11-20-browser-semantics-soundness.md](2026-11-20-browser-semantics-soundness.md)（攻撃 4、合成）
- 木の節: browser-semantics-soundness/D2

## 問い

モデルは断片（取得と CORP、ナビゲーションと COOP、エージェントクラスタの鍵、入れ子と Permissions Policy、リダイレクトの列）に分かれている。各断片が他の断片に仮定していること（例: 取得の性質は、文書の COEP が正しく決まっていることを仮定する）と保証していることを明示し、仮定が循環するところ（COEP の意味はエージェントクラスタの鍵を仮定し、DIP はそれを上書きする、など）を、帰納の形の assume-guarantee の規則で扱えるかを確かめる。

問いの出し方（ユーザーの判断）: 作業の木の効きが高・中の節がなくなるまで進める（/goal）。Claude は、互いにぶつからない作業の束に分けて並行で進め、この記録はその束の 1 つ。

## 前提

- 規則は、循環する仮定には時間に沿った帰納（前の段で保証されたものを次の段で仮定する）を使うものを考える（McMillan などの循環 assume-guarantee の規則）。
- モード: 構成的。

対立仮説:

- R1 扱える。循環は時間の段で切れ、各断片の検査を合わせると全体の性質が出る。
- R2 扱えない循環がある（同じ時点で互いを仮定する）。
- R3 仮定を書き出すと、どの断片にも無い前提が見つかる（モデルの欠落）。

設定の欠陥: 断片の分け方はモデルの作者が決めたもので、仕様の構造と一致するとは限らない。

## 条件を変える

subagent が、断片ごとの仮定と保証を書き、仮定の循環を分け、段ごとの帰納の検査と、1 つにまとめた状態機械での検査を TLC で行った（[compose/](models/site-isolation/compose/RESULTS.md)、Contracts.tla、Compose.tla、contracts.tsv）。既存のモジュールは変えずに使った。規則の理論は、McMillan の要旨と、Rushby の PVS での確かめを検索で確かめ、Abadi と Lamport、Namjoshi と Trefler は記憶。筆者は報告を読んだ。

**断片と契約**（確定した文書ごとの述語）

<!-- data-source: original（subagent の契約の要約） -->
| 断片 | 保証 |
| --- | --- |
| 方策の容れ物の COEP | 安全な文脈でなければ unsafe-none |
| DIP | none でなければ、安全なオリジンの最上位の文書 |
| COOP とグループとリダイレクトの連鎖 | 最上位の成員では、解析した COOP が same-origin-plus-COEP ⇔ グループが concrete |
| 成員（popup はグループから、子は適合の検査から） | concrete のグループ ⇒ COEP が require-corp か credentialless |
| エージェントクラスタ | DIP があればクラスタの mode は concrete、無ければグループの mode。mode が none でなければオリジンで区切る。クラスタと過去の鍵の表が食い違わない |
| getter | crossOriginIsolated ＝ クラスタの mode が concrete かつ Permissions Policy が許す |
| 取得 | 互換の COEP か DIP があり、結果が不透明 ⇒ 資格情報を送っていないか CORP の同意 |

全体の性質: crossOriginIsolated な文書が受ける別オリジンの no-cors の中身は、資格情報なしか CORP の同意つきで、文書はオリジンで区切られる。

**循環と扱い**

- 子のナビゲーションと方策の容れ物: 段をまたいでは、子は前の確定の親の COEP を読む。1 回の確定の中では、子の文脈 → 安全な文脈 → 子の COEP → 適合の検査と流れ、断片の間では同時の循環だが、値の間では循環しない。確定を 1 つの段として扱った。
- 親や開いた側を通した成員の保証、過去の鍵の表と既存のクラスタを通したエージェントクラスタ: 前の確定を通るので、時間に沿った帰納で解けた。
- リダイレクトの段をまたいだ COOP: 整礎の再帰（Chain が Tail で再帰）。
- 値の水準の同時の循環は無かった（循環する定義は RECURSIVE でなければ SANY が拒み、届く RECURSIVE は Chain だけ）。「COEP の意味はエージェントクラスタの鍵を仮定する」という循環は無く、鍵から取得へ戻る辺は DIP の鍵を通るものだけ。

**規則**: 安全性についての McMillan の形の帰納。最初の確定がすべての保証を立て、すべての保証を満たす前の状態から、各段が足すものについて保証を立て、保証から全体の性質が出る。

**TLC**

- すべての仮定のもとで（DIP を鍵に含む）: 段ごとの検査と、最後の含意がすべて真。
- 保証を 1 つずつ抜く（23 分）: どの保証を抜いても、少なくとも 1 つの検査が崩れる（空の契約は無い）。
- 鍵に DIP を含めない: 子と popup の段が崩れ、TLC はエージェントクラスタの保証を崩れた契約として名指した。
- 変異体 false:nav-coep-adherence: 子の段が成員の保証で崩れた。
- 1 つにまとめた状態機械（文書 2 つで 2,489 状態、3 つで 66,684 状態）で誤りなし。鍵に DIP を含めない版と変異体の版は、深さ 2 で全体の性質の反例。段ごとの検査と、すべての設定で一致した。

**見つかった穴**

1. エージェントクラスタの鍵が DIP を含むこと（合成がこれに依る）。SpecIsolation の鍵に DIP の部分は無く、DIPExtension にはエージェントクラスタが無い。反例: DIP のある最上位の文書（COOP unsafe-none）に、COEP の無い同一オリジンの子が同じクラスタに入って隔離される。筆者の確かめ: DIP の草案（2026-11-21 に取得）は、obtain a similar-origin window agent の 3 段目を、文書の鍵があればそれを鍵に入れるよう書き換えている（2026-11-21 の informal-extension の記録で読んだ本文）。前提は草案に根拠があり、欠けているのはモデルの側。
2. 「安全」の 2 つの意味。EffectiveDIP はオリジンの安全さを、方策の容れ物は最上位の安全な文脈を使う。DIP の保証を仮定しないと、取得の契約がすべての記録で崩れる。
3. DIP は最上位だけ。DIP の文書の子には、DIP に対する適合の検査が無い。
4. DIPExtension の「変わらない」の検査が、Mixed Content を足してから偽（前から既知）。
5. 写していない: 受け継ぐ文書と局所のスキームの文書、iframe が開いた popup。
6. Permissions Policy は合成を支えていない（導出による、TLC では別に確かめていない）。

読み取れること:

- R1（扱える）が、写した断片について、DIP の鍵の前提のもとで当たった。
- R2（扱えない循環がある）は、断片の水準でだけ当たり（確定の中）、値の水準では当たらなかった。
- R3（どの断片にも無い前提が見つかる）が当たった。合成を支える前提（鍵が DIP を含む）が、どのモジュールにも無かった。仮定と保証を書き出したことの効き目。

## 結果を攻撃する

経緯を知らない subagent 2 体（形式手法、ブラウザの実装と仕様の編集）に、A2・C4・A1・C9・B2a と B2d・D2 の結論をまとめて攻撃させた（ユーザーの判断: 作業の木の高・中がなくなるまで）。形式手法の観点は記憶で論じ、ブラウザの観点は仕様の本文と PR を 2026-11-24 に確かめた。筆者は、モデルの性質が CHOOSE と Cardinality を使わないこと（CHOOSE は反例の証人の定義だけ）と、compose/ の契約に liveness が無いことを確かめた。

## 結論

断片ごとの仮定と保証を書き、循環は、値の水準では無く（断片の水準の同時の循環は確定を 1 段として扱えた）、時間に沿った帰納と整礎の再帰で解けた。契約は安全性だけなので、循環の規則の付帯条件を満たす。合成は、エージェントクラスタの鍵が文書の cross-origin isolation の鍵（DIP から作る、オリジンと mode）を含むという前提に依り、この前提は DIP の草案に根拠があるが、モデルのどのモジュールにも無い（F9）。1 つにまとめた検査は文書 2〜3 個に限られ、文書の数の打ち切りは示していない。

生き残った選択肢: R1（前提つき）と R3。R2 は断片の水準でだけ。
